# 科學論文寫作專家規範 (Scientific Paper Skill)
當使用者要求撰寫、修改或檢查學術論文時，請嚴格執行以下四大模組規範：

## 1. Abstract（摘要撰寫規範）
* **結構要求**：採用標準四段式邏輯（Background 背景與痛點 → Methods 核心方法 → Results 關鍵量化數據 → Conclusion 學術貢獻），字數嚴格控制在 150–250 字之間。
* **語言風格**：使用精煉、客觀的學術英語（第三人稱或被動語態），避免空泛形容詞（如 *groundbreaking*, *revolutionary*），強調具體提升幅度（如 *improves accuracy by 12.4%*）。
* **禁止事項**：摘要中嚴禁出現文獻引用（`*cite{}`）、縮寫未定義即使用，以及本文未提及的實驗結論。

## 2. 本文撰寫與 IMRAD 架構（Introduction, Methods, Results, Discussion）
* **Introduction**：採用「漏斗式」寫法。先交代大領域背景，接著指出現有文獻的具體研究缺口（Research Gap），最後條列本文的 2–3 項核心貢獻。
* **Methods**：確保可重現性（Reproducibility）。明確列出實驗參數、資料集規模、演算法流程與評估指標。
* **Results vs. Discussion 分離**：Results 僅客觀陳述數據與圖表趨勢；Discussion 則負責解釋「為什麼」會產生此結果、與前人研究的異同，以及研究限制（Limitations）。
* **去 AI 味潤飾**：避免高頻 AI 轉折詞（如 *In conclusion*, *Furthermore*, *delve into*, *testament to*），改用直接、邏輯連貫的因果句型。

## 3. Citation（文獻引用與零幻覺原則）
* **嚴格防幻覺**：**絕對禁止憑空捏造任何文獻、作者、年份或 DOI**。若缺乏真實文獻來源，必須明確標註 `[CITATION NEEDED: 需補充關於 XXX 的文獻]`。
* **BibTeX 格式維護**：新增引用時，同步更新專案中的 `references.bib`，確保 Citation Key 命名統一（建議格式：`第一作者姓氏_年份_關鍵字`，例如 `smith2025transformer`）。
* **引用查核**：檢查內文所有 `*cite{}` 是否皆存在於 `.bib` 檔中，並確認無「有列未引」的冗餘文獻。

## 4. 圖表生成與排版（Figures & Tables）
* **數據圖表（Figures）**：當使用者提供 CSV/JSON 實驗數據時，優先撰寫並執行 Python 腳本（使用 `matplotlib` 或 `seaborn`）生成高解析度（300 DPI 以上）的向量圖（`.pdf` 或 `.svg`），配色需符合色盲友善（Colorblind-safe，如 Okabe-Ito 色票）並具備清晰的座標軸標籤與誤差線（Error bars）。
* **三線表規範（Tables）**：在 LaTeX 中一律使用 `booktabs` 套件（`*toprule`, `*midrule`, `*bottomrule`）繪製專業學術三線表，嚴禁使用垂直分隔線（`|`），並將該組最佳數據以 `*textbf{}` 加粗標示。
* **獨立自明性（Self-contained Captions）**：每張圖表的 Caption 必須完整說明圖表內容、實驗條件與縮寫定義，讓讀者不看內文也能理解圖表含義。
請謹慎使用程式碼。

# 工程應用科學論文寫作規範 (IEEE / ACM / Nature)

當使用者要求撰寫、修改、繪圖或轉換論文格式時，請嚴格執行以下規範：

## 1. 雙階段寫作工作流（Markdown + Pandoc → LaTeX）
* **階段一：Markdown 撰寫規範（Pandoc 相容語法）**
  * **引用語法**：在 `.md` 檔中一律使用 Pandoc 標準引用格式 `[@smith2025keyword]`（多篇引用以分號隔開 `[@key1; @key2]`），禁止混用原生的 `*cite{}`，以確保後期能無痛轉換為 LaTeX 的 `*cite{}` 或 `*citep{}`。
  * **交叉引用（Cross-references）**：使用 `pandoc-crossref` 標準語法標記圖表與公式，例如圖表標記 `{#fig:architecture}`、表格標記 `{#tbl:results}`、公式標記 `{#eq:loss}`，內文引用寫作 `@fig:architecture`、`@tbl:results`。
  * **數學公式**：行內公式使用 `$...$`，獨立區塊公式使用 `$$...$$` 並於末尾加上標籤 `{#eq:label}`。
* **階段二：Pandoc 轉譯與 LaTeX 微調規範**
  * 當使用者要求轉換格式時，協助檢查並執行對應的 Pandoc 轉譯指令（包含 `--citeproc` 或 `--natbib`/`--biblatex` 參數），並針對目標期刊的 `.cls` 模板進行雙欄（Two-column）跨欄圖表（`figure*` / `table*`）與版面微調。

## 2. 目標期刊風格與結構適配（Engineering Applications）
請根據使用者指定的目標期刊，自動切換寫作側重點與結構：
* **IEEE 系列（如 IEEE Trans. / Access）**：
  * **Abstract**：150–250 字，強調「工程痛點 → 系統架構/演算法設計 → 量化效能指標（延遲、吞吐量、準確率）→ 實際部署價值」。
  * **結構**：重視系統架構圖（System Overview）、硬體/實驗環境配置（Experimental Setup）、消融實驗（Ablation Study）與計算複雜度分析。
* **ACM 系列（如 ACM Trans. / 頂會）**：
  * **Abstract**：150–200 字，強調問題定義的嚴謹性、方法的創新性與基準測試（Benchmark）的統計顯著性。
  * **結構**：注重再現性（Artifacts / Code availability）、演算法虛擬碼（Algorithm pseudocode）與邊界條件討論。
* **Nature 系列（如 Nature Communications / Scientific Reports / npj）**：
  * **Abstract**：150 字以內（無分段、無引用），第一句需用跨領域學者都能理解的語言破題，最後一句點出對該工程或科學領域的廣泛影響力（Broader Impact）。
  * **結構**：採用 IMRAD（Introduction, Results, Discussion, Methods，注意 **Methods 常置於文末**），強調現象背後的物理/工程機制解釋，而非單純堆疊工程參數。

## 3. Citation 與零幻覺原則
* **嚴格防幻覺**：**絕對禁止憑空捏造任何文獻、作者、年份或 DOI**。若缺乏真實文獻來源，必須明確標註 `[CITATION NEEDED: 需補充關於 XXX 的文獻]`。
* **BibTeX 同步維護**：新增引用時，同步更新專案中的 `references.bib`，確保 Citation Key 格式統一為 `第一作者姓氏_年份_關鍵字`（如 `chen2025edge`）。

## 4. 工程級圖表與數據視覺化規範
* **數據圖表（Python 自動生成）**：讀取 CSV/JSON 實驗數據時，撰寫並執行 Python 腳本（`matplotlib` / `seaborn`）輸出高解析度（300 DPI 以上）的向量圖（`.pdf` 供 LaTeX 使用，並同步輸出 `.png` 供 Markdown 預覽）。
* **期刊版面尺寸適配**：繪圖時主動詢問或預設單欄寬度（IEEE/ACM 單欄約 `3.5 inches`，雙欄跨欄約 `7.16 inches`；Nature 單欄 `89 mm`，雙欄 `183 mm`），確保字體在縮放後仍清晰（8–10 pt）。
* **配色與標註**：強制使用色盲友善色票（如 Okabe-Ito 或 Viridis），必須包含誤差線（Error bars / 陰影信賴區間）與明確單位。
* **學術三線表**：在 Markdown 中使用標準 Pipe Table 並附帶 `: 表格標題 {#tbl:label}`；轉換為 LaTeX 後一律改用 `booktabs` 套件（`*toprule`, `*midrule`, `*bottomrule`），最佳數值以粗體標示。
請謹慎使用程式碼。

在量子控制領域，QICK（Quantum Instrumentation Control Kit）與 QubiC（Qubit Control）是兩大主流的開源 FPGA 框架。兩者雖然都基於 AMD-Xilinx 的 RFSoC 平台，但在處理邏輯與指令架構上有明顯的設計差異。
1. QICK (由 Fermilab 開發)
QICK 的核心哲學是將量子實驗視為一系列精確計時的「脈衝序列」。

* 核心組件：tProcessor
* 邏輯架構：這是一個自定義的 64 位元軟核心處理器（Soft-core Processor）。它擁有一個 48 位元的中央主時鐘（Master Clock），確保所有通道的時序同步。
   * 指令集：tProcessor 執行自定義指令，這些指令會觸發下游的「訊號產生器（Signal Generator）」與「讀取模組（Readout Blocks）」。
* 讀取與產生邏輯：
* 訊號產生器：脈衝包絡（Envelope）預先存儲在 FPGA 的 Block RAM (BRAM) 中。
   * 數位上/下變頻 (DUC/DDC)：在 FPGA 邏輯中實現 NCO（數控振盪器）與混合器，直接在數位領域處理 I/Q 訊號。
* 實作細節：其 HDL 實作高度模組化，提供 [proj.tcl](https://github.com/openquantumhardware/qick/blob/main/firmware/README.md) 腳本供 Vivado 自動重建 Block Design，並使用 AXI4-Stream 進行高速數據傳輸。 [1, 2, 3, 4] 

2. QubiC (由 LBNL 勞倫斯柏克萊實驗室開發)
QubiC 2.0 傾向於分散式架構，特別針對大規模位元擴充與即時反饋進行優化。

* 核心組件：分散式多核心 (Distributed Multi-core)
* 邏輯架構：QubiC 採用「一個核心控制 1-3 個通道」的設計。這種並行設計避免了單一執行緒在處理大量位元時產生的瓶頸。
   * 參數化控制：支援在執行過程中動態更新脈衝的振幅、相位與頻率，而無需重新編譯。
* 讀取控制流：
* 中路測量與前饋 (Mid-circuit Measurement & Feed-forward)：QubiC 2.0 強化了 FPGA 內部的狀態判別與邏輯跳轉（if-else），延遲極低。
   * DSP 鏈路：包含數位混頻器、濾波器以及用於狀態分類的積分器。
* 實作平台：目前主要運行在 [Xilinx ZCU216](https://lbl-qubic.gitlab.io/) (Gen 3 RFSoC) 上，利用 PYNQ 框架來橋接 Python 層與底層的 FPGA 邏輯。 [5, 6, 7, 8, 9, 10] 

3. QICK 與 QubiC 邏輯架構對比

| 特性 [2, 6, 8, 10, 11] | QICK (Timed Processor) | QubiC (Distributed Cores) |
|---|---|---|
| 處理器設計 | 單一/集中式計時處理器，同步性強 | 分散式輕量核心，適合大規模並行 |
| 脈衝管理 | BRAM 預存包絡 + 定時觸發 | 參數化指令，可在執行間動態更新 |
| 硬體目標 | ZCU111, ZCU216, RFSoC4x2 | 主要針對 ZCU216 (Gen3) 優化 |
| 軟硬體介面 | 高度依賴 Python API 與 tProc 指令 | 支援 gate-level 到 pulse-level 的編譯器棧 |

如果您需要修改韌體，[QICK 的 GitHub 倉庫](https://github.com/openquantumhardware/qick) 提供了完整的 Vivado Tcl 腳本與模組源碼；而 QubiC 2.0 則更強調與 LBNL 的軟體棧深度整合，適合需要自定義分散式控制邏輯的場景。 [4, 10]
